# 开发板验证清单

本文档用于在真实开发板上验证 A/B 双镜像 IAP 流程。仓库代码只有在主机测试和本清单中的必测项全部通过后，才进入提交或推送阶段。

当前 STM32F407ZGT6 实测记录见 [STM32F407ZG 开发板验证记录](board-validation-results-stm32f407zg.md)。

## 1. 连接开发板后先记录

开始测试前补齐以下信息，不根据猜测选择烧录命令或 Flash 地址：

- 开发板型号、MCU 完整料号和 Flash 容量。
- BOOT0/BOOT1 跳帽或启动选项状态；Flash 冷启动测试必须确保 BOOT0 为低电平。
- 调试器型号及连接方式，例如 ST-Link、J-Link、DAPLink 或板载调试器。
- 使用的 SDK、编译器、构建工具和版本。
- Bootloader、Slot A、Slot B、Boot Control 的起始地址、长度和擦除粒度。
- 启动地址要求、向量表重定位方式、看门狗和复位原因寄存器。
- 固件传输入口，例如 UART、CAN、USB、以太网或调试器直接写入。
- 串口参数、日志抓取方式和恢复模式入口。

## 2. 上板前静态检查

- [ ] Flash 分区互不重叠，所有地址和长度按擦除页对齐。
- [ ] Boot Control 不与 Bootloader 或任一 APP slot 共用擦除页。
- [ ] Slot 容量能容纳镜像头、APP 镜像及必要的对齐填充。
- [ ] APP 链接地址与对应 slot 地址一致。
- [ ] 跳转前正确关闭中断、SysTick 和外设，并设置 MSP、VTOR 与复位向量。
- [ ] Flash 驱动遵守解锁、擦除、编程、校验、加锁和缓存同步要求。
- [ ] Boot Control 写入方案能够处理掉电；若暂未实现双副本，必须明确记录风险。
- [ ] 主机侧 `cmake --build build` 和 `ctest --test-dir build --output-on-failure` 通过。

## 3. 基础硬件测试

| 编号 | 测试项目 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| HW-01 | 调试连接 | 连接调试器，读取芯片 ID 和 Flash 容量 | 识别信息与实际 MCU 一致，连接稳定 |
| HW-01B | 冷启动源 | BOOT0=0 后真实断电重启，读取 PC 或应用状态 | PC 不在系统 ROM，执行用户 Flash Bootloader |
| HW-02 | Flash 擦写 | 在专用测试页执行擦除、写入、读回 | 擦除值、写入数据和读回数据完全一致 |
| HW-03 | 边界保护 | 测试未对齐地址、越界地址和受保护区域 | 驱动明确拒绝，Bootloader 区域未被修改 |
| HW-04 | 单镜像启动 | 仅写入 Slot A 和默认 Boot Control 后复位 | 每次都从 A 启动，日志和跳转地址正确 |
| HW-05 | 看门狗 | 启动 APP 后停止喂狗 | 在预期时间内复位，复位原因可识别 |

## 4. IAP 闭环必测项

| 编号 | 测试项目 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| IAP-01 | 正常升级 | A 运行时写入合法 B，标记 pending 后复位 | Bootloader 校验 B，尝试次数加 1，并启动 B |
| IAP-02 | 升级确认 | B 自检通过后调用确认接口，再次复位 | B 成为 active，pending 清空，尝试次数归零 |
| IAP-03 | 未确认回滚 | B 启动后不确认，连续触发复位 | 达到最大尝试次数后回到 A，B 不再被选择 |
| IAP-04 | CRC 损坏 | 修改 B 载荷但保留原 CRC，标记 pending 后复位 | B 被拒绝，pending 清空并回到 A |
| IAP-05 | 镜像头损坏 | 分别破坏 magic、header size、header version、image size | 每种损坏都被拒绝，A 仍可启动 |
| IAP-06 | Boot Control 损坏 | 破坏 magic、slot 值或尝试次数 | 检测到控制块无效，进入设计规定的初始化或恢复路径 |
| IAP-07 | 无有效镜像 | 同时破坏 A 与 B | 不跳转到无效地址，进入 recovery |
| IAP-08 | 存储读失败 | 在读 B 或 Boot Control 时注入错误 | 错误被上报，不把瞬时读错误误判为镜像损坏 |
| IAP-09 | 控制块写失败 | 在记录启动次数或确认时注入写错误 | 不启动未记录的 pending 镜像，进入 recovery 或错误处理 |
| IAP-10 | 非 pending 确认 | A active、B 仅有效但未 pending 时尝试确认 B | 操作被拒绝，active 仍为 A |

## 5. 掉电测试

每个阶段至少重复 10 次，恢复供电后读取 Boot Control 和两个 slot 的状态：

- [ ] 擦除目标 slot 期间掉电。
- [ ] 写镜像头期间掉电。
- [ ] 写镜像载荷的 25%、50% 和 90% 时掉电。
- [ ] 镜像写完但尚未标记 pending 时掉电。
- [ ] 写 Boot Control 期间掉电。
- [ ] 新 APP 首次启动但尚未确认时掉电。
- [ ] 确认 Boot Control 期间掉电。

任何一次恢复都不得跳转到未通过完整校验的镜像。若单副本 Boot Control 无法满足该要求，应先实现双副本或日志式提交，再继续推送流程。

## 6. 结果记录

每项测试保存以下证据：

- 测试日期、代码提交或工作区快照标识。
- 开发板、MCU、调试器和工具链版本。
- 使用的 A/B 固件版本、文件大小和 CRC32。
- 串口日志、调试器日志、复位原因和关键 Flash 读回值。
- 实际结果、通过或失败结论、失败复现步骤。

## 7. 推送门禁

只有满足以下条件才准备推送远端：

- [ ] 主机单元测试全部通过且无编译警告。
- [ ] HW-01 至 HW-05 全部通过。
- [ ] IAP-01 至 IAP-10 全部通过。
- [ ] 掉电测试达到约定次数且没有启动无效镜像。
- [ ] 已复核 Flash 分区、链接脚本和 Boot Control 掉电安全策略。
- [ ] 测试证据完整，工作区差异经过最终审查。
